# Human variant annotation (REST-based, research use)

Helpers load with this skill (`kernel.py`): `normalize_variant_ids`, `left_align`, `vep_annotate`, `clinvar_lookup`, `gnomad_frequencies`, `pp3_bp4_points`, `acmg_evidence_hints`, `annotate_variants`, `parse_variant`, `api_call`. They need `pandas` + `requests` (env `genomics`). `bcftools` is only for VCF files.

## Use / do not use
- Use: tens to a few thousand variants; per-variant evidence tables; VUS triage; checking labels/frequencies for a benchmark set.
- Not for: whole-exome/genome VCFs (REST limits: 200 variants/POST, ~15 req/s, gnomAD throttles bursts) — use local VEP with offline cache, or `bcftools csq`. Variant calling and GWAS belong to the neighbouring variant-calling / GWAS skills. Protein language-model scoring (ESM) belongs to the `esm` skill if present in your catalog (none was found when this skill was written); Evo 2 likewise.

## Workflow
1. **Pin the build first.** GRCh38 → `rest.ensembl.org`; GRCh37 → `grch37.rest.ensembl.org`. gnomAD: `gnomad_r4` (GRCh38) / `gnomad_r2_1` (GRCh37). Every helper takes `assembly=`; variant keys are `chr-pos-ref-alt` without `chr` prefix.
2. **Normalize.** VCF files: `bcftools norm -f ref.fa -m -any -c w in.vcf -Oz -o out.vcf.gz` (left-align + split multiallelics; default `-c e` aborts on REF mismatch, `-c w` warns). Single variants: `normalize_variant_ids(["rs80357906","NM_007294.4:c.5266dup","17-43057062-T-TG"])` → DataFrame with `variant_id`, one row per ALT allele (rs1801133 gives G>A and G>C), `note` set for unresolved ids or REF≠genome. It calls `left_align` (Ensembl `/sequence/region`, no FASTA) because recoder returns the dbSNP-style right-shifted form: rs80357906 → `17-43057065-G-GG` from recoder, `17-43057062-T-TG` after left-align (the form VEP, gnomAD and ClinVar SPDI agree on).
3. **Consequences.** `vep_annotate(ids, assembly)` → one row per variant using the MANE Select transcript (GRCh38 only), else canonical: gene, transcript, consequence, impact, hgvsc/hgvsp, `am_pathogenicity`, `am_class`, `revel`, colocated rsIDs. Extra VEP REST options go through `params={...}` (names/defaults: rest.ensembl.org/documentation/info/vep_region_post).
4. **ClinVar.** `clinvar_lookup(rsids=[...], variants=[SNV keys], api_key=None)` → `classification` (germline), `review_status`, `last_evaluated`, `conditions`, `variation_id`, `canonical_spdi`. Indels: look up by rsID (SPDI of dups is expanded, e.g. `GGG:GGGG`, so coordinate matching is SNV-only).
5. **gnomAD.** `gnomad_frequencies(keys, assembly)` → `status` found / absent / error (absent = not in dataset, not an error), `ac`, `an`, `af`, `hom`, `faf95_popmax` (+ population). r4 uses the joint exome+genome record; r2_1 sums exome+genome.
6. **Everything at once.** `annotate_variants(inputs, assembly="GRCh38", ncbi_api_key=None)` merges steps 2–5 and appends `acmg_hints`; `df.attrs["provenance"]` holds one dict per source (endpoint, release/build, timestamp). Save it next to the table. ClinVar uses the first matching record per variant; call `clinvar_lookup` for all records.

## Verified behaviours (2026-10-02)
- Ensembl REST: release 116, REST 15.12 (both servers). Limit 55000 req/h (~15/s); on 429 honour `Retry-After`. Max POST 200 (VEP region/hgvs/id, variant_recoder).
- VEP region input: `"17 43057062 . T TG . . ."`; the response `input` echoes the string. Plugins are query flags: `AlphaMissense=1`, `REVEL=1` (REVEL non-commercial), `CADD=1`, `SpliceAI=1`, `dbNSFP=...`. Plugin scores live inside each `transcript_consequences` entry (`alphamissense: {am_pathogenicity, am_class}`, `revel`), only for missense; frameshifts return None.
- `variant_recoder`: do not mix rsIDs and HGVS in one request (a mixed batch mis-resolved `NM_007294.4:c.5266dup` to chr18 variants); one unparsable id returns HTTP 400 for the whole batch (helper retries singly); HGVS-only batches silently drop failures — join on `input`. Gene-symbol HGVS (`BRCA1:c.…`) is not supported; use NM_/ENST accessions. HGVS requests were slow (minutes); rsIDs take seconds.
- GRCh37 server: no MANE; `am_class` labels are `pathogenic`/`benign` (helper maps to `likely_pathogenic`/`likely_benign`).
- ClinVar esearch is text-based: `rs1801133[RSID]` returned 4 records of which one is the variant; the helper keeps records whose dbSNP xref matches. Fields `germline_classification`, `clinical_impact_classification`, `oncogenicity_classification` replace the old `clinical_significance`. Stars: practice guideline 4; expert panel 3; criteria provided, multiple submitters, no conflicts 2; single submitter or conflicting 1; no criteria/classification 0. ClinVar classifications can be non-pathogenicity terms (rs1801133: `drug response`).
- NCBI E-utilities: 3 requests/s without key, 10/s with `api_key` (NCBI Insights, 2017-11-02). Pass `ncbi_api_key` for batches. NCBI also requests `tool`/`email` params; the helpers omit them — add a contact email only from `host.get_user_email()`.
- gnomAD API: GraphQL `variant(variantId:, dataset:)`, fields `exome|genome|joint {ac an homozygote_count hemizygote_count faf95{popmax popmax_population} populations{id ac an}}`; `joint` exists for gnomad_r4 only. Dataset enum (live introspection): gnomad_r4, gnomad_r4_non_ukb, gnomad_r3(+subsets), gnomad_r2_1(+subsets), exac. No published rate limit was found; an introspection burst returned HTTP 429, so the helper spaces requests 2 s apart and backs off. `filters` such as `discrepant_frequencies` (seen on rs1801133 joint) are not surfaced by the helper — query them if QC matters.

## Missense scores and ACMG/AMP framing (research support only — not a clinical classification)
- **AlphaMissense** (Cheng 2023, Science): via VEP REST `AlphaMissense=1`. Developer classes: likely_benign < 0.34, likely_pathogenic > 0.564, else ambiguous. Offline: Zenodo 10.5281/zenodo.8208688 (`AlphaMissense_hg38.tsv.gz`, `_hg19`, `_aa_substitutions`, `_gene_*`, `_isoforms_*`; columns CHROM POS REF ALT genome uniprot_id transcript_id protein_variant am_pathogenicity am_class; canonical transcripts, GENCODE v32 hg38). Licence: Zenodo README says CC BY-NC-SA (non-commercial); the Ensembl REST page states CC-BY — check before commercial use.
- **ACMG/AMP calibration.** The developer 0.564 cut does not reach even Supporting evidence (Bergquist 2025). Use `pp3_bp4_points(tool, score)`: points + = PP3, − = BP4 (±1 Supporting, ±2 Moderate, ±3 between, ±4 Strong), 0 = indeterminate. Tables: REVEL (Pejaver 2022 Table 2; Bergquist 2025 Table 1) and AlphaMissense (Bergquist 2025 Table 1; e.g. ≥0.792 Supporting, ≥0.906 Moderate, ≥0.990 Strong; ≤0.169 benign Supporting). Use one pre-chosen tool; do not stack tools. Pejaver warns PP3 can double-count with PM2/BS1/PM1/PS1/PM5.
- **Frequency criteria.** BA1: AF > 5% (Richards 2015; many VCEPs use gene-specific values). BS1: AF greater than expected for the disorder (needs prevalence/penetrance). PM2: ClinGen SVI (4 Sep 2020) recommends PM2_Supporting; VCEPs may differ. Use `faf95_popmax` for filtering-AF logic; the helper's BA1 hint uses overall AF — check popmax manually.
- Worked values: MTHFR c.665C>T (rs1801133): gnomAD r4 AF 0.318, REVEL 0.842 (PP3_Moderate by score), AlphaMissense 0.6324 (indeterminate by calibration; developer class likely_pathogenic), ClinVar `drug response` — a common variant where BA1 overrides in-silico evidence. MLH1 c.1169A>G p.Glu390Gly (VCV004801634, ClinVar VUS, 2 stars): absent from gnomAD r4 (PM2_Supporting), REVEL 0.509 and AlphaMissense 0.3272 both indeterminate. BRCA1 c.5266dup (rs80357906): ClinVar Pathogenic, expert panel; gnomAD r4 AC 109/1,613,912; null variant, no missense scores.
- Not covered by helpers: PVS1, PS/PM functional and segregation evidence, splice predictors (SpliceAI via `params={"SpliceAI":1}`), gene-specific VCEP rules.

## Leakage and provenance (for any model evaluation using these variants)
- ClinVar labels and predictors overlap: REVEL, MutPred2, BayesDel etc. were trained on ClinVar/HGMD-like data; AlphaMissense was trained on population-frequency data, not ClinVar labels, but its thresholds and Bergquist/Pejaver calibrations use ClinVar 2019 (Pejaver: ClinVar VCF Dec 2019, gnomAD v2.1 AF < 0.01, VUS/0-star/conflicting removed, tool training variants excluded where available; Bergquist: ClinVar 2019 for calibration, ClinVar 2020 post hoc, no extra training-set filtering for AlphaMissense/ESM1b). For a fair test use ClinVar submissions dated after the predictor's training cutoff, or the Pejaver/Bergquist-style training-set removal.
- Record in every output: assembly; Ensembl release (`/info/data`) and REST version; ClinVar build and last-update (`einfo`: e.g. Build260929-0200.1, 2026/09/29) — ClinVar classifications change, so archive the release or export labels with dates; gnomAD dataset id; predictor version (AlphaMissense database 2023-09-19, REVEL via Ensembl plugin); tool versions (bcftools, pandas); query date. `annotate_variants` provenance covers the API-side items.

## Pitfalls
- Mixed builds: gnomAD/ClinVar/VEP keys differ between GRCh37 and GRCh38; check `note` for REF≠genome.
- Un-normalized indels fail to match gnomAD/ClinVar; always left-align.
- ClinVar absence ≠ benign; gnomAD absence is coverage-dependent.
- Transcript choice changes hgvsp and consequence; the helper reports MANE Select (GRCh38) or canonical — state it.
