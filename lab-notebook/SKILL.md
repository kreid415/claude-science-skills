# Lab notebook

A chronological, append-only record of what was done, seen and decided, written **as it happens**. It
complements `paper-outline`: the notebook is the raw record, and the outline is the curated argument.

## Files (project repo, `notebook/`)

| file | holds |
|---|---|
| `README.md` | conventions and the notebook timezone (`- timezone: America/New_York`); created by `nb_init` |
| `YYYY-MM-DD.md` | one page per day; entries in time order |
| `INDEX.md` | generated by `nb_index()`: entries by experiment, project-wide entries, decisions, open issues |

## Entry format (written by `nb_entry`; never hand-edit)

```
## NB-20261002-03 · 2026-10-02T14:31:05-04:00 · DECISION · E01
**Use ComBat before PCA**
- author: user | agent:<frame id prefix>
- <type-specific fields>
- links: repo@<HEAD>; artifact:<VERSION_ID>; job:<id>; <path>
- refs: NB-20261002-02
<!-- sha256=<this entry> prev=<previous entry> -->
```

| type | required fields | use when |
|---|---|---|
| EXPERIMENT | `aim`, `plan` | an experiment is designed or launched (inputs, params, seed, where it runs) |
| RESULT | `ran`, `observed` | output exists: what ran and what it shows, with numbers read from the artifact |
| FINDING | `claim`, `based on` | an interpretation is drawn (cite the RESULT IDs it rests on) |
| DECISION | `decision`, `alternatives`, `rationale`, `decided by` | any choice of method, parameter, dataset or scope, or a drop/keep call |
| ISSUE | `problem`, `impact`, `next` | a bug, failure, confound or dead end |
| NOTE | `text` | anything else: a meeting point, an idea, something the user dictated |
| CORRECTION | `corrects`, `was`, `correct` | an earlier entry is wrong; the old entry stays in place |

Optional extra fields go after the required ones. A value given as a list becomes sub-bullets. `experiment` is the
outline's `E01` ID (matching `experiments/01_name/`); omit it for project-wide entries. `repo@<HEAD>` is added
automatically.

## Helpers (`kernel.py`, auto-loaded)

- `nb_init(root, project, timezone)`: creates the notebook README (never overwrites).
- `nb_entry(root, type, title, fields, experiment=None, author="agent", links=None, refs=None, commit=True)`: appends
  an entry, rebuilds the index and git-commits. It holds a file lock, so concurrent agents get unique IDs and an
  unbroken chain. It refuses unknown types, missing required fields, and refs to entries that don't exist.
- `nb_check(root)`: verifies the hash chain (detects edited, deleted or reordered entries), ID uniqueness,
  timestamp order, required fields, and that refs point to earlier entries.
- `nb_index(root)`: rebuilds `INDEX.md`.
- `nb_entries(root)`: parsed entries, for answering history questions.
- `nb_export_decisions(root, "audit/DECISIONS.md")`: writes the decisions file for the `reproducible` audit bundle.

## Workflow

1. **Locate the repo root.** Use the project's git repo (a granted host path or the `reproducible` scaffold).
   On first use, call `nb_init` with the user's timezone (ask once if unknown). Run `nb_check` before the first
   entry of a session.
2. **Write entries at the moment of the event.** Don't batch them at the end of a session:
   - before submitting a job or running an experiment → EXPERIMENT, with params, seed, inputs and target host;
   - when it finishes or fails → RESULT or ISSUE, with links to the artifact/job;
   - when the user or you choose between options → DECISION. Record who decided, and the user's words when they
     decided;
   - when a result is interpreted → FINDING, citing the RESULT IDs in `based on` / `refs`;
   - when the user says "note that…" → NOTE with `author: user`.
3. **Numbers come from the artifact.** Read values back from the output file or artifact and link it. Never
   retype them from memory or prose. If an entry turns out wrong, write a CORRECTION; never edit the page.
4. **Propagate.** If a RESULT, FINDING or DECISION changes the paper's argument, update the outline (`paper-outline`)
   and put the notebook ID in its changelog line (e.g. "E02 dropped (NB-20261002-03)"). For decisions, project
   memory keeps only a one-line pointer (`Decision NB-… : <one line>`). The notebook entry is the record.
5. **Save** the day's page and `INDEX.md` as artifacts `notebook_YYYY-MM-DD.md` and `notebook_INDEX.md`. Find prior
   versions with `host.artifacts(filename=..., exact=True)` and pass `version_of` so each keeps one history.
6. **Report** each entry's ID in the reply (one line each), so the user can refer to it.

## Rules

- Append-only. Never edit, delete or reorder entries. If `nb_check` reports a break, tell the user what broke;
  don't repair it by rewriting hashes.
- One event per entry, with short fields. Detail belongs in the linked artifact or code, not the entry.
- Record failures and dead ends as faithfully as successes.
- Timestamps come from `nb_entry`. Don't backdate. A late entry about earlier work says so in a field (e.g.
  `- happened: 2026-10-01 afternoon`).
